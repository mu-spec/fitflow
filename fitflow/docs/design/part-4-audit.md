## Findings and decisions

### Workouts and actual routes
`AppRoutes` has Home's adaptive preview/player, Programs overview/detail/session preview/player, custom new/detail/edit/player, Library/detail and skill-tree overview/family. There is no independent custom-list route: Workouts itself owns the saved custom list. Keep that architecture. Home remains the adaptive-today owner, linked by a modest text action rather than another generated workout card. Existing Workouts orders Library first, adds a generic Recommended heading, a Programs entry, active and recommended cards, duplicate custom-create entry, skill trees, then custom list. Eliminate generic placeholder hierarchy and duplicate create entry. Programs entry + one active continuation, custom heading/list/create, then Explore Library/skill trees. Goal-matched recommendation remains available in Programs browse; no second recommendation card needed in Workouts. Preserve all destination paths and controller calls.

### Programs
Five catalog-defined plans have factual names, focus, description, weeks and session counts. Recommendation is the existing selected-goal match, not a rating. `AdaptiveProgramStatus` already filters completed IDs against the definition and identifies the first incomplete session. `hasProgress` means a saved record exists (including zero completions). Use that for Not started/In progress/Completed, and exact session counts, never fabricated percentage copy. Overview currently has many tags but lacks a consistent status when fresh. Detail places lengthy copy/tags ahead of actions and hides count for fresh plans. Show purpose, structural facts, exact progress/next context, then unchanged action callbacks and week groups. Completed/Next/Upcoming are presentation labels for existing completed/next/planned states; every existing session preview remains inspectable, no invented locking. Keep program start/switch/restart confirmations and Player handoff/origin untouched. Current overview/detail silently substitute empty progress while loading/error; replace that presentation with truthful loading/retry, not a false fresh state.

### Custom workouts
Workouts is the saved list, with create, detail and edit/delete overflow. Current cards calculate estimated duration using the canonical resolver, show target duration separately, and derive main movement focus. Preserve those calculations and every confirmation/delete/storage call. Reduce chip/card noise, make View the main action and Edit secondary; native overflow keeps delete. Empty state gets one Create action. Builder is already functional and is not a redesign target; leave ordering/sections/add/remove/rename/workload/replacement unchanged.

### Exercise Library
Active catalog has 88 exercises. Search matches name, muscles, movement, equipment and tags (trimmed/case-insensitive). Filter semantics are AND across groups, OR within groups; preserve `exercise_library_filter.dart` byte-for-byte. Existing four quick filters are genuine metadata. Advanced sheet contains movement/difficulty/equipment/body position; preserve all categories and matching. Current fixed Column header can consume the whole short/keyboard viewport at large type. Use a single lazy sliver scroll with stable TextEditingController, visible query/clear, horizontally scrollable quick filters, wrapping controls and textual active advanced selections. No per-query animation, no per-row controller, no whole-list eager building. Cache the immutable active catalog list, not search results. Name + focus + useful equipment is sufficient per row; default prescription/level belongs deeper. Native actions retain focus/tap semantics.

### Exercise detail and skill trees
Detail currently has a 180px blank illustration promise, then prescription and progression before instructions. Replace placeholder with a small icon component (an explicit future media insertion point, no promised media). Lead with factual catalog description/setup/how-to, then muscles and existing cautions/breathing. Keep defaults and environment characteristics deeper. Display catalog instructions verbatim, no added safety/medical claims. Existing progression resolver provides current/easier/harder and ordered step context; retain it, remove duplicate numeric decoration and raw enum/rank display. Skill tree resolver independently reports movement-level fit and setup eligibility, NOT mastery, completion, unlocks or a single assessed current exercise. Do not pretend a current exercise was measured. Use canonical human-facing movement level choices, readable wrapping statuses, restrained family summaries and capped reading width. Preserve truthful caveat and actual neighborhood links.

### Progress/history/analytics
`TrainingAnalyticsEngine` derives valid saved workouts, current/previous rolling seven-day counts/main sets/planned durations, eight trend buckets, movement training and consistency. Recovery remains its separate unchanged engine; capability is current snapshot, not historical growth. Current screen exposes four headline cards plus comparison/chart/consistency/movement/capability/recovery BEFORE history. Reduce to three real headline signals (saved workouts, last-seven-day completions, planned time), then recent history; detailed trends/training and current movement/recovery live behind disclosure. Existing eight-period chart is meaningful, but a simple labeled proportional bar list with a text equivalent is preferable to a cramped eight-column fixed-height chart at 2×. No invented streak, readiness, calories or health score. Motion only native selection/disclosure with canonical reduced-motion duration; no chart animation.

`CompletedWorkout` stores ID, completion time, planned/estimated duration, counts and effective ordered exercises. It does NOT store display name, custom/program origin, elapsed duration, replacement-original provenance or dates for capability change. Do not infer origins from ID strings or label estimated time as elapsed. Use Completed workout + localized date/time, explicitly planned/estimated time and real counts; show effective exercises in existing history detail. Existing history shows ten entries then a non-actionable remaining count: add a presentation-only Show more disclosure in batches, preserving ordering and data. Empty Progress should explain completed workouts appear and have one Home/training CTA; no empty dashboard panels. Error copy must not expose exception internals.

## Accessibility / responsive / performance audit
Use canonical theme/token width caps, typography/stat roles, native 48dp actions, wrapping layouts, heading semantics and non-color-only state. No clamp on text scale. Cover 320/390/430/600/900 and landscape at 2× in light/dark. Key risks: fixed search header, chip ellipsis for long labels, skill-node chip widths, history trailing duration Row, numeric capability meter, fixed-height chart, program completed heading Row, duplicate nested card/button taps, error states with no retry. Keep readable single columns where two columns would only add clutter. No grid of equal tiles. Disclosure uses SystemMotion standard/zero; list filtering is immediate. No new image/network/blur/shader/dependency costs. Device performance remains unmeasured until Oppo A12 QA.
